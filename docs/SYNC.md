# 无账号跨设备同步

HolaDone 不要求邮箱、手机号或密码。第一台设备生成 20 位同步码，另一台设备通过二维码或手动输入同步码加入同一同步空间。

## 安全模型

- 同步码只保存在用户设备的 `localStorage`，不会以明文上传。
- 浏览器使用同步码派生空间 ID、写入凭证和 AES-256-GCM 密钥。
- Vercel Function 只接收空间 ID、派生后的写入凭证和密文。
- Upstash Redis 保存密文，不保存可直接解密数据的同步码或 AES 密钥。
- 二维码把同步码放在 URL fragment 中，fragment 不会随 HTTP 请求发送给服务器。
- 拿到同步码的人可以读取、修改或删除这份学习进度，因此同步码应按密码管理。

这不是账户恢复系统。两台设备都丢失且没有保存同步码时，无法找回或解密云端记录。

## 同步内容

- 当前轮次、模式、随机顺序和中途练习位置
- 每日完成数量与连续学习记录
- 已掌握轮次及看义／听音两种掌握进度
- 永久错题统计、各模式活跃复习状态、跨学习日恢复进度及兼容清除标记
- 重音判定、音效和发音速度

## 合并规则

- 已掌握轮次和两种掌握进度取并集。
- 每日完成数量取两端较大值，避免同一份历史被反复相加。
- 新版错题记录按最后一次变更时间合并；离开错题本只关闭活跃状态，不删除永久统计。旧版清除标记仍用于避免旧设备把已经解决的活跃错题重新带回。
- 当前练习位置和设置采用学习数据更新时间较新的设备。

应用会在启动、重新回到页面和本地学习记录变化后同步。断网时本地练习不受影响，下次联网再合并。云端密文每次写入都会续期；停止使用 400 天后自动删除，也可在设置中立即删除。

## Vercel / Upstash 配置

在 Vercel Marketplace 为本项目连接 Upstash Redis，确保 Production、Preview 和 Development 环境存在：

```text
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
```

也兼容旧式 Vercel KV 变量名：

```text
KV_REST_API_URL
KV_REST_API_TOKEN
```

连接后重新部署。`api/sync.js` 会把每个同步空间保存为一个 Redis 字符串记录，并限制单份密文最大为 200 KB。
